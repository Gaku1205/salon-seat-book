# 仕様書

アプリの「何を・どう動かすか」を書く。AIは作業の前に必ずここを読む。

## 目的

hair room HARUの予約サイト。お客さんがスマホでメニューと担当と空き時間を選んで予約し、お店は木の台の予約帳で1日を見て閉じられる（元のメモ：美容室の予約サイト）

## 予約の決まり

- 店の名前は「hair room HARU」
- メニューは3つ。値段は未定なので画面に出さない
  - カット：60分。スタッフは60分ずっと手が要る
  - カラー：90分。最初の15分と最後の15分が施術（スタッフの手が要る）、間の60分は放置（スタッフの手は空く）
  - パーマ：120分。スタッフは120分ずっと手が要る
- 担当は「スタッフA」「スタッフB」「スタッフC」の3人（仮の名前）。お客さんは3人のどれか、または「おまかせ」を選ぶ
- 席は4つ（席1〜席4）。お客さんには席を選ばせない。空いた席をお店の側で割り当てる
- 時間は30分の枡で数える。営業は仮に 10:00〜19:00。開始できるのは 10:00〜18:00 の30分ごと（終わりが19:00を過ぎてもよい）。定休日は決めない
- 予約できるのは、今日から1か月先の同じ日まで（例：11月22日なら12月22日まで。次の月に同じ日が無ければ、その月の最後の日まで）
- 予約できるのは、開始の1時間前まで（ちょうど1時間前は予約できる）
- 時刻はすべて日本の時刻（UTC+9）で数える
- 予約は無料。支払いはお店で
- 空いている、の数え方：その開始時刻に、
  - 担当のスタッフが、施術の時間（カラーなら最初と最後の15分）に、ほかの予約の施術と重ならない
  - 席のどれか1つが、そのメニューの全部の時間（カラーなら90分）、ほかの予約と重ならない
  - なので、カラーの放置中に、同じスタッフが別の席で別のお客さんのカットに入れる（例：10:00のカラーの施術は10:00〜10:15と11:15〜11:30。その間の10:15〜11:15は手が空くので、同じスタッフが10:30から別の席で別のカラーに入れる。施術は10:30〜10:45と11:45〜12:00で、11:15〜11:30と重ならない。なお開始が30分ごとなので、空いた60分にカット60分がちょうど入る開始時刻は今は無い）
  - 「おまかせ」は、3人のうち誰か1人が空いていれば空き
- 予約は確定するとその場で決まる（お店の承認は無い）。保存先は `BookingStore`（`src/lib/booking-store.ts`）のインターフェースで、今はサーバーのメモリ上の実装だけ。サーバーが入れ替わる・再起動すると予約は消える（本番で使うには、人間がデータベースを用意して、別Issueで差し替える）
- 空きは、見本の予約（`src/lib/sampleBookings.ts`、今日と明日に数件）と保存済みの予約をあわせて数える（`bookingsOn`）。トップの予約帳・`/reserve` の時間の一覧・確定の直前の確認・お店の予約帳は、どれもこの同じ入口で予約を数える
- お店は、休み（日付ごと。その日は終日閉じる）と、閉じた時間（日付＋30分の枠ごと。席は問わず店全体の4席すべて）を持てる。休みの日は空きを出さない。閉じた枠と、メニューの全部の時間（席が埋まる時間。カラーなら90分）が少しでも重なる開始時刻は空きに出さない（例：12:00 を閉じると、カットは 11:30・12:00、カラーとパーマは 11:00・11:30・12:00 などから始められない）。開ければまた空きに出る
- 休み・閉じた時間の保存先は `ClosureStore`（`src/lib/closures.ts`）のインターフェースで、今はサーバーのメモリ上の実装だけ。予約と同じく、サーバーが入れ替わる・再起動すると消える
- 確定の直前に、もう一度その枠の空き・休み・閉じた時間と締め切り・1か月先までを確かめる。入れなければ保存せず「埋まった」結果にする。確定は1件ずつ順番に処理する（同じ枠を同時に確定しても1件だけ通る）
- 確定したら席と担当を割り当てる。席は番号の小さい空いた席、担当は選んだ人（「おまかせ」は A・B・C の順で最初に空いている人）

## 画面

### トップ（`/`）

- 木の台の上に白い帳面を置いた画面。帳面の上に店名「hair room HARU」と、その日の日付（例：「11月22日（日）」）
- 帳面には、席4列（席1〜席4）×30分の枡（10:00〜18:30 の行）の1日の表
- 埋まった枡には、担当の名前とメニューが手書きの文字で書かれている。カラーの放置中の枡には「放置」と書く
- 空いた枡は押せる。押すと予約の選択（`/reserve?date=日付&time=時刻`）へ進む。予約の締め切り（1時間前）を過ぎた枡と、1か月先より先の日は押せず、斜線で消してある。お店が閉じた枡（閉じた時間の行）と休みの日の枡も押せず、斜線で消してある
- 埋まった枡には、見本の予約と保存した予約をあわせて書く
- 帳面の上で、前の日・次の日へめくれる（今日から1か月先まで）。日は `?date=YYYY-MM-DD` で持つ
- 帳面の下に「予約する」の入口（`/reserve`）

### 予約の選択（`/reserve`）

- 上から順に、1. メニュー → 2. 担当（おまかせ・スタッフA・B・C）→ 3. 日付（今日から1か月先まで、横に並ぶ）→ 4. 時間
- 選んだ内容はURLのクエリで持つ：`menu`（`cut`・`color`・`perm`）、`staff`（`any`・`a`・`b`・`c`）、`date`（`YYYY-MM-DD`）、`time`（`HH:MM`）。選ぶたびにURLが変わる。お客さん情報の入力（`/reserve/confirm`）はこのクエリを受け取る
- 時間は、メニューと担当と日付が選ばれたときだけ、空いた開始時刻だけを並べる。空きが無い日は「この日は空きがありません。ほかの日をお選びください」
- トップの枡から来たとき（`date`・`time` がある）は、その日と時刻を選んだ状態で始める。その時刻が空いていなければ、時刻の選択は外す
- 4つ全部選ぶと、選んだ内容のまとめと「お名前・連絡先の入力へ」が出る。押すと `/reserve/confirm?menu=…&staff=…&date=…&time=…` へ、選んだ4つをそのまま引き継いで進む
- スマホで押しやすい大きさ（押せる物は高さ48px以上）

### お客さん情報の入力（`/reserve/confirm`）

- `/reserve` と同じクエリ（`menu`・`staff`・`date`・`time`）を受け取る。上に選んだ内容のまとめ（メニュー・担当・日時）と「選び直す」（選んだ内容を保って `/reserve` へ）、その下に入力フォーム
- クエリが足りない・不正なとき：「予約の内容が読み取れませんでした。はじめから選び直してください」と `/reserve` への「予約の選択へ戻る」を出す。内容は正しいがもう空いていない（埋まった・締め切りを過ぎた）とき：「この時間は埋まってしまいました。ほかの時間をお選びください」と、選んだ内容を保った `/reserve` への「予約の選択へ戻る」を出す。どちらもフォームは出さない
- 入力は「お名前」「電話番号」「メールアドレス」の3つ（全部必須）。「この内容で予約する」を押すと Server Action で検証して確定する。送信中はボタンを押せず「予約しています」
- 検証（`src/lib/customer.ts`）。エラーは項目の下に日本語で出し、入力した文字は残す。前後の空白は取る
  - お名前：空は不可。連続する空白（全角含む）は1つにする。30文字まで。制御文字は不可
  - 電話番号：全角の数字・ハイフンは半角にそろえる（ー、−、‐ などハイフンに見える字も「-」として扱う）。数字とハイフンだけで、ハイフンは数字の間にだけ置ける。数字は10〜11桁。保存するのはハイフンを除いた数字
  - メールアドレス：全角は半角にそろえる。100文字まで。「名前@ドメイン.末尾」の簡単な形だけを見る（空白不可、@は1つ、ドメインに「.」が要る）
- 確定したとき埋まっていたら、保存せず、同じ画面の上に「この時間は埋まってしまいました。ほかの時間をお選びください」と、選んだ内容を保った `/reserve` への「時間を選び直す」を出す（入力した内容は残す）
- 確定できたら `/reserve/done?id=予約ID` へ移動する

### 予約の完了（`/reserve/done`）

- 予約IDで保存先から予約を引き、お店の名前「hair room HARU」・メニュー・担当（おまかせなら決まった担当）・日時・お名前・予約番号（予約ID）を出す。「予約は無料です。お支払いはお店で」と、トップ（予約帳）へ戻るリンク（文言は「予約帳へ戻る」）
- IDが無い・見つからないとき（サーバーが再起動した場合も）：「予約が見つかりませんでした。お手数ですが、予約の選択からやり直してください」と `/reserve` へのリンクを出す

### お店の合言葉（`/shop/login`）

- スタッフ3人が同じ合言葉で開く。合言葉はサーバーの環境変数 `SHOP_PASSPHRASE` から読む（コード・テスト・docs には書かない）。未設定のときは誰も開けない（どの合言葉でも失敗）
- 帳面に「お店の予約帳」の見出し、「合言葉」の入力欄（文字は伏せる）と「開く」のボタン。Server Action で確かめる
- 合ったら、Cookie を付けて `/shop` へ移る。Cookie は httpOnly・sameSite=lax・本番は secure・期限は7日。中身は合言葉そのものではなく、期限と、合言葉を鍵にした HMAC（SHA-256）の値。比べるときは `timingSafeEqual` を使う。合言葉を変えると、前の Cookie は使えなくなる
- 違ったら、同じ画面に「合言葉が違います」を出す。回数の制限は付けない。ログアウトの操作は作らない
- 判定は `src/lib/shop-auth.ts`（合言葉が合うか・Cookie の値が開いていると言えるか。環境変数の値は引数で受け取る）

### お店の予約帳（`/shop`）

- Cookie が無い・合わないときは `/shop/login` へ移す（予約帳の中身は出さない）
- 帳面の上に店名と「お店の予約帳」、その日の日付。日は `?date=YYYY-MM-DD` で持つ（既定は今日）。前の日・次の日へめくれる。過去の日も見られる。先は1か月先まで（それより先の「次の日」は押せない）。読めない日・1か月先より先の日は今日にする
- 帳面には、トップと同じ席4列×30分の枡（10:00〜18:30 の行）。見本の予約と保存した予約（`bookingsOn`）を、担当の名前とメニューを入れて書く
- 閉じる・開ける操作は、今日から1か月先までの日だけ（過去の日は見るだけ。操作のボタンを出さない）
  - 帳面の上に「この日を休みにする」（休みの日は「休みをやめる」）のボタン。休みの日は日付の下に「休み」と出し、空いた枡はすべて斜線にする
  - 休みでない日、空いた枡を押すとその行（時刻）を選び、帳面の下に「10:30 この時間を閉じる」と「やめる」が出る。閉じた枡（その行の空いた枡すべてに「閉」）を押すと「10:30 この時間を開ける」と「やめる」が出る。選んだ時刻は `?date=…&at=HH:MM` で持つ
  - 閉じる・開ける・休みは Server Action で、実行の前に必ず Cookie を確かめる（開いていなければ何もしない）。実行したら同じ日の `/shop` に戻る
  - その枠（30分）に席の時間がかかる予約が既にあれば閉じない：「予約が入っている時間は閉じられません」。その日に予約が既にあれば休みにしない：「予約が入っている日は休みにできません」。予約の確定と同じ順番待ちの列で処理する（確かめてから閉じるまでの間に予約が割り込まない）
